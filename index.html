ODPM DISPUTE AUTOMATION · USER GUIDE

争议交易辅助处理脚本
用户教程

帮助你在订单查询完成后，先确认订单数量，再可控地批量联系消费者。关键确认仍由用户完成，脚本只负责处理当前页面结果。

脚本版本 0.7.0适用页面：dispute-transactions支持 UI 模式 / API 模式
重要提示：本脚本会执行真实的“是否联系消费者”操作。开始前请核对当前页面、订单总数和处理数量；API 模式速度更快，但应先完成一次人工操作以捕获认证信息和请求格式。
一、准备工作二、开始处理三、监控与排错

一、准备工作

安装用户脚本管理器

浏览器需要先安装 脚本猫、油管猴 等用户脚本管理器。将 odpm-dispute-automation.user.js 导入并启用。

打开正确页面

登录 ODPM 后进入 https://odpm.oceanpayment.com/dispute-transactions。页面加载完成后，右上角会出现“ODPM辅助处理”面板。

确认账号具有处理争议交易的权限。
确认当前页面已经加载完成，表格和分页组件可见。
首次使用建议先点击一次页面原有的“是否联系消费者”，并在弹窗中点击“确定”。
在微信中打开：电脑本地的 HTML 文件无法直接在微信内打开。请先将本教程上传到公司静态网站、Web 服务器或 GitHub Pages，获得以 https:// 开头的网页地址，再把该地址发送到微信。微信只能打开可访问的网页链接，不能直接访问你电脑上的文件路径。

二、开始批量处理

UI 模式：推荐首次使用

UI 模式会模拟人工逐单点击，速度较慢，但过程最直观。

1
设置处理数量

“处理数量”留空或填 0 表示处理全部；填写正整数表示最多处理指定数量。建议首次先填写较小数量进行验证。

2
点击“UI模式”

脚本先统计查询结果，随后弹窗显示总记录数、计划处理数量和当前页可联系订单数。

3
人工确认后继续

核对弹窗信息，确认无误后点击“确定”。脚本会逐单点击“是否联系消费者”，再点击业务弹窗中的“确定”。

4
必要时暂停或停止

“暂停”会等待当前可安全停顿的位置；“停止”会中止后续处理，已完成的操作不会回滚。

API 模式：适合熟悉流程后使用

API 模式直接请求系统接口并按并发数处理，效率更高。它仍然会先获取订单列表并弹窗确认。

启动前条件

  • 已人工点击并确认过一次“是否联系消费者”。
  • 面板 API 状态显示 Token 和 Payload 已捕获。
  • 页面查询已经完成，列表数据可正常显示。

参数建议

  • 并发数范围为 1 到 10。
  • 建议从默认值 3 开始。
  • 遇到接口限流或失败时降低并发数。

准备好后点击“API模式”，确认订单数量和并发数。API 模式有成功记录时会在约 1 秒后自动刷新页面。

建议的首次流程：先使用 UI 模式处理少量订单，确认页面状态和日志正常；熟悉后再使用 API 模式，并从并发数 3 开始。

三、监控、日志与排错

面板功能用途注意事项
进度信息显示已处理数量、成功、失败、跳过、当前页、当前订单和用时。失败订单不会阻塞后续订单，处理结束后查看失败日志。
诊断页面检查表格、按钮、分页、弹窗、Token 和 Payload 是否被识别。API 模式启动前优先使用此功能确认状态。
显示日志查看普通操作日志、警告和错误详情。日志最多保留最近 500 条。
导出日志下载当前日志为文本文件，便于留档或反馈问题。日志可能包含订单标识，请按公司规定保存和传递。

常见问题

面板没有出现

确认脚本已启用、页面地址匹配，并刷新页面。若仍无面板，检查用户脚本管理器的控制台错误。

提示未捕获 Token 或 Payload

先在页面上人工完成一次“是否联系消费者”及弹窗确认，再点击“诊断页面”。不要在未捕获认证信息时反复尝试 API 模式。

没有找到订单

确认查询已经执行、表格已经刷新，以及当前账号是否有权限看到结果。脚本只处理当前页面显示的查询结果。

弹窗处理失败

脚本会对“确定”进行有限重试。若仍失败，点击“停止”，记录导出的错误日志并人工检查订单状态。

停止后的处理：停止不会撤销已经提交的联系操作。重新启动前，建议刷新页面并重新确认查询结果，避免重复处理。

每次执行前的快速检查

当前页面已经完成查询，表格内容与业务预期一致。
查询结果总数和可联系订单数量已核对。
处理数量没有超过本次应处理范围。
已确认当前账号、页面和订单状态正确。
处理过程中有人观察面板，异常时能及时点击“暂停”或“停止”。
